# QA complementar — S2-23 e integração com o acervo

Validação de 22/10/2026 sobre a branch `fix/s2-23-aprovacao-relatorios`, integrada à main `d00c801`. A PR #54 foi mesclada durante a revisão; as correções seguem em branch complementar. A migration de revisão é a **022**, preservando a 021 de relações entre PBIs que entrou na main.

## Correções demonstradas

1. `ProjectDetail` usa permissão de PO/admin e estado do projeto. Desenvolvedores leem relatórios, mas não veem aprovação/reprocessamento. Testes cobrem PO, admin, dev, carregamento, erro HTTP e preservação do relatório.
2. Relatórios concluídos ficam aguardando aprovação. O aceite identifica revisor, data e SHA-256 e compara a revisão exibida com a revisão atual sob bloqueio transacional. Alterações de conteúdo/origem invalidam o aceite e removem os trechos anteriores. Busca e chat recusam relatórios não revisados, inclusive quando há um chunk inserido diretamente na fixture.
3. A migration 022 remove somente trechos de relatórios legados e exige revisão humana; preserva outros tipos de conteúdo. Reprocessamento não duplica chunks.
4. O mock do Ollama foi movido para contêiner/rede Docker próprios. A porta publicada é somente loopback, com token por execução, corpo de até 256 KiB, limite de histórico e erros controlados. O teste de segurança verifica 401/400/413 e recuperação da próxima requisição válida.
5. O teste transacional atualiza um relatório indexado, observa remoção dos chunks/revogação do aceite, aprova a nova versão e observa a fila pendente **antes do rollback**. Após rollback, conteúdo, hash de aprovação, estado indexado e chunks anteriores permanecem intactos.
6. Dois workers concorrentes recebem análises distintas; uma terceira reivindicação não obtém os trabalhos reservados. Reservas vencidas e respostas antigas não sobrescrevem a revisão atual.
7. A integração da S2-05 revelou uma lacuna adicional: o expurgo cancelava documentos, mas não reservas de relatórios. O expurgo agora revoga a aprovação e invalida suas reservas na mesma transação. Uma conclusão atrasada não repovoa o índice.
8. A revisão adicional encontrou uma corrida com aceite em trânsito: após o expurgo, uma requisição antiga poderia reaproveitar a mesma revisão. O expurgo também incrementa a revisão; o aceite enviado por uma tela antiga retorna 409, antes de qualquer nova publicação.

## Reprodução

Com Docker disponível e dependências de `backend`, `frontend` e `e2e` instaladas, na raiz:

```powershell
npm run build --prefix backend
npm test --prefix backend
npm run build --prefix frontend
npm test --prefix frontend
npm run test:integration:indexing --prefix backend
npm run test:integration:review --prefix backend
docker build -t sinapse-s209-ai-test ai-service
npm run test:integration:copilot --prefix backend
```

Os comandos criam bancos/arquivos temporários e os removem ao terminar. Não usam nem limpam o banco de desenvolvimento. O teste de navegador usa Edge no Windows ou `E2E_CHROME_PATH`; no CI usa Chrome.

## Cobertura complementar e limites

- **S2-05/S2-08:** confirmação do nome do projeto, autorização administrativa, expurgo de relatórios/documentos, preservação do outro projeto, busca vazia após exclusão, snippet, identificação da fonte e navegação ao trecho/execução foram exercitados no navegador autenticado.
- **S2-03/S2-04:** os testes PostgreSQL cobrem idempotência, revisão da origem, reabertura, arquivamento, mudança de projeto, reservas concorrentes e recuperação de falha. O teste de estados executa oito sequências determinísticas de 80 operações.
- **S2-13/S2-14:** aceite, edição e descarte explícitos foram exercitados pela UI, com verificação de autor, origem e `ai-accepted`/`ai-edited` persistidos. Dev recebe 403 e não vê os controles; o serviço de IA indisponível não impede resolver sugestões já existentes nem preservar edição manual.
- **S2-06/S2-17:** não declaradas concluídas. Permanecem pendentes a decisão do PO/time sobre GRF-01/08, critérios de relevância e aceite da avaliação semântica. As fixtures e o relatório anterior em `QA_SEARCH_V2_2026-10-02.md` são referência, não novo aceite.
- Embeddings/respostas do modelo são determinísticos/simulados nos testes integrados. Os testes demonstram contratos e persistência; não certificam a qualidade semântica do Ollama local.
